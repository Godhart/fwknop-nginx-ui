# Архитектурные решения 2.0.0

## ADR-001: SPA на сетевом уровне

fwknop CMD_CYCLE_OPEN вызывает фиксированный helper; команды клиента запрещены.
Набор trusted_v4 имеет timeout в ядре. До изменения nginx-конфигурации
авторизация уже определяет, получит клиент сайт или заглушку. Решение действует
для всех созданных через UI сайтов; nginx allow/deny и обновление списков IP
при каждой SPA не требуются. IPv6 SPA не обещается: UDP daemon предыдущего
решения принимает IPv4. IPv6 не становится обходом: попадает на заглушку,
кроме явно заданных bypass CIDR.

## ADR-002: host network и systemd

Один официальный контейнер, host network, без port mappings. У dedicated
gateway нет нужды в Docker bridge; так сохраняется source IP и не возникает
обход INPUT через Docker DNAT. FORWARD закрыт. systemd запускает proxy только
после успешного firewall и повторяет применение перед стартом. Docker restart
policy выключена, чтобы daemon не опубликовал сайты раньше firewall при boot.
Остановка firewall unit не удаляет правила. Полный root администратор может
обойти систему; это не граница защиты от администратора.

## ADR-003: Nginx UI владеет nginx и ACME

Ansible делает одноразовый bootstrap и затем не переписывает nginx-файлы.
Не применяется read-only mount, ограниченный редактор, внешний Certbot,
запрет терминала, DNS plugins или Docker features. UI и Docker socket образуют
доверенный административный контур. SSH tunnel и loopback listener отделяют
его от внешнего ingress. Полный UI не превращается в панель nft/fwknop:
для SPA сохраняется CLI/Ansible.

## ADR-004: challenge исключение и TLS заглушки

HTTP-01 разрешён только на выделенном URI и направлен на challenge backend
UI, не на произвольный сайт. DNS-01 работает без исключений. TLS заглушка не
может скрыть проверку сертификата: доверенные сертификаты обслуживаемых
имён назначаются ей через UI. Редирект строится из remote_addr, не из Host
или клиентских forwarding headers, без переноса приватных query parameters.

## ADR-005: совместимость и границы

Ubuntu 24.04 и 26.04 допускаются playbook; пакетные зависимости устанавливаются
из репозиториев целевого Ubuntu. Сам факт допуска ОС не является результатом
живого интеграционного теста. Нет обещания строгого разрыва всех соединений по
TTL, индивидуальных ролей портов на ключ, одного IP на ключ или HTTP/3.
Настройки дополнительных TCP/UDP-портов сохранены. Existing connections
обслуживаются conntrack, как в предыдущей ветке.

## ADR-006 (2.0.1): совместимость с WebSocket self-check

Сохраняем inbound X-Forwarded-Proto/Host на локальном UI proxy согласно
официальной проверке Nginx UI. В схеме с прямым HTTP SSH-туннелем внешнего TLS
терминатора нет, но bootstrap должен проходить проверку установки UI.
Maps не используются публичными сайтами. Их входные заголовки не становятся
источником доверия для SPA, client IP или redirect. Административный listener
остаётся 127.0.0.1:9080. Существующий исправленный UI файл сохраняется.
