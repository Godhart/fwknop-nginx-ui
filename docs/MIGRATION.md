# Переход с 0.x

2.0.0 — новая структура, не in-place апгрейд. Рекомендуется новая VM с тем же
публичным адресом после проверки или переключение DNS на новый адрес.

1. Сохраните старый inventory, Vault, конфиги, сертификаты и данные контейнеров.
2. Разверните 2.0 на новой VM, используйте новые ключи либо явно перенесите
   подходящие ключи в vault_spa_clients. Проверьте rescue и SPA с разных IP.
3. Воссоздайте сайты в UI, импортируйте сертификаты либо выпустите новые через
   UI. DNS-01 позволяет подготовить сертификаты до переключения DNS.
4. Проверьте direct origin protection, заглушку, HTTP-01, websocket и TTL.
5. Переключите адрес/DNS, обновите SPA_SERVER у клиентов.

Если используется прежняя VM, необходим согласованный maintenance window:
остановите и отключите старые nginx, контейнеры и ACME timers; освободите
80/443/8081/8444/9000/9080/9180; сохраните старую spa_gate; удалите старые unit
файлы spa-nginx-docker после backup. Не запускайте старые и новые firewall
скрипты одновременно. Старый fwknop unit с тем же именем будет заменён.
Playbook обнаруживает старый spa-nginx-docker.service и останавливается, но
эта проверка не является полным детектором всех сторонних сервисов.

Для отката используйте snapshot всей VM, а не только предыдущий Compose:
формат БД Nginx UI при обновлениях может меняться. Не переносите старые
Ansible-generated сайты поверх новых данных UI без просмотра конфигурации.
